# MOBION / Channel Box — отчёт об аудите безопасности

**Дата:** 29 октября 2026 года  
**Исходник:** `channel_box-mono_miniapp_fixed6-1.zip`  
**Область:** Python Telegram-бот, FastAPI Mini App, админ-панель, PostgreSQL DAL, платежные webhook, Docker.

## Исправлено

1. **Crypto Pay / CryptoBot.** Все входящие webhook проверяются по заголовку `crypto-pay-api-signature`: HMAC-SHA256 от **сырых байтов** HTTP-тела с ключом SHA256(CryptoBot API token). Запросы без подписи или с подменённым телом отклоняются до обработки платежа. Добавлена проверка `update_type`.
2. **Проверки платежей.** Ужесточена проверка суммы и валюты в CryptoBot и суммы в Tinkoff; проверяется связь заказов услуг/ремонтов с ожидаемым платёжным методом и известным ID ЮKassa. Отсутствующая/некорректная сумма не трактуется как успешная. Сохранилась дополнительная проверка статуса в API платёжных систем.
3. **Защита от повторов.** Пометка ремонта «оплачено» выполняется под блокировкой строки в БД, с отдельным флагом первого подтверждения, чтобы повторный webhook не дублировал уведомления.
4. **Telegram Mini App.** Запрещены дублирующиеся параметры `initData`, слишком большие данные, дата авторизации в отдалённом будущем, пустой токен и ненормальный тип ID пользователя; сохраняется HMAC-проверка и 24-часовое ограничение возраста сессии.
5. **Ограничение запросов.** Для webhook требуется JSON-объект и тип `application/json`, размер тела ограничен 64 КиБ даже при потоковой передаче. Исключения не раскрывают пользователям внутренние детали.
6. **Безопасность страниц.** Добавлены заголовки `no-store`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, CSP для Mini App (с SHA256-хэшем встроенного JavaScript) и страниц временного доступа; страницы временного доступа запрещено открывать во фрейме.
7. **Временные ссылки.** Ограничена длина токенов, повторно проверяются срок жизни и отзыв временной ссылки в транзакции с блокировкой строки.
8. **Логи.** Убрано логирование подписи Tinkoff, некоторых подробных ответов платёжных API и содержимого CryptoBot webhook.
9. **База данных.** Строка подключения формируется через `SQLAlchemy URL.create`, что корректно экранирует пароль с `@`, `:`, `/`, `#`, `?` и другими спецсимволами.
10. **Docker и шаблон настроек.** Контейнер запускается без прав root, исправлен bind mount `./logs:/src/logs`, добавлен переход на консольное логирование, если файл недоступен. Из `.env.template` убраны конкретные реквизиты получателя.
11. **Зависимость h11.** `h11` обновлена с `0.14.0` до `0.16.0` из-за CVE-2025-43859 (HTTP request smuggling). Остальные версии не обновлялись без проверки совместимости.

## Проверки

- `python -m compileall -q src` — успешно.
- `python -m unittest discover -s tests -v` — **13 тестов из 13** успешно (Telegram HMAC, просроченные/будущие сессии, изменённые webhook, JSON/лимиты, URL БД, CSP).
- `node --check src/webapp/static/admin.js` — успешно.
- `node --check` встроенного JS из `src/webapp/static/index.html` — успешно.
- Тестовые запросы FastAPI выполнены без реальных платежей и без изменения БД.

## Что остаётся проверить до размещения в production

- **Не выполнялся полноценный сквозной запуск:** в среде аудита нет действующих API-токенов, PostgreSQL и установленных исходных версий всех библиотек. Реальные платежи и подписки, SMTP/Telegram callbacks, Docker-сборка и браузер Telegram требуют отдельного стенда.
- **Не выполнен полный аудит уязвимостей всех сторонних пакетов:** в окружении недоступен Python package registry, поэтому `pip-audit` / установка зависимостей не запускались. В частности, `aiohttp==3.11.13` остаётся старой версией; обновление требует проверки совместимости с `aiogram==3.18.0`. `starlette==0.46.1` также требует отдельного обновления вместе с подходящей версией FastAPI; при этом Mini App больше не использует её уязвимый `FileResponse` для отдачи файлов.
- **Транзакции подписок:** логика отмечает платёж подтверждённым до завершения создания/продления подписки. Если процесс оборвётся в этот момент, нужен механизм восстановления (очередь/повторная сверка) либо атомарная транзакция. В текущем патче этот бизнес-процесс не переписывался, чтобы не менять реальные платежи без интеграционных тестов.
- **Несколько экземпляров бота:** антиспам-кэши в памяти каждого процесса не обеспечивают распределённую блокировку; при горизонтальном масштабировании нужен Redis либо ограничения в БД/прокси.
- **Логи в Docker:** при bind mount `./logs:/src/logs` разрешите запись UID `10001` для папки `logs` на сервере, иначе приложение продолжит логировать в stdout, но файл не сохранится. Пример: `mkdir -p logs && sudo chown -R 10001:10001 logs`.
- Размещайте WEB_URL только на HTTPS, ограничивайте доступ к Postgres, держите `.env` и реальные секреты вне репозитория. Проверяйте подписи webhook не отключая их в production.
