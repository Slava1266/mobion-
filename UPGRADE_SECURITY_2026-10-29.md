# CHANNEL BOX / MOBION — усиление безопасности, доработка fixed6+ (29.10.2026)

## Что изменено в этой версии

1. **Подписки:** календарные даты теперь рассчитываются в `Europe/Moscow` через `ZoneInfo`, независимо от часового пояса Docker. Существующие поля `start_date`/`end_date` остаются `TIMESTAMP WITHOUT TIME ZONE`; формат данных не меняется. Для **старых строк, созданных на сервере с другим часовым поясом**, прежде чем запускать cron, необходимо определить фактический часовой пояс хранения и выполнить проверенную миграцию — автоматического преобразования старых строк нет.
2. **Просроченные подписки:** проверка при старте и затем ежечасно в `:05`, а не один раз в сутки. Проверка активной подписки в API/боте/ссылках/админке теперь учитывает `end_date`. При ошибке удаления из канала подписка остаётся помеченной для повторной попытки; администратор получает уведомление. Добавлена повторная проверка перед удалением из канала и после операции Telegram, чтобы не удалять оплативших клиентов при гонке.
3. **Продление:** `max(end_date, текущее время)` перед прибавлением срока; две конкурентные выдачи/продления одному пользователю сериализованы транзакцией с блокировкой строки пользователя. При оплате нового плана того же канала меняется `plan_id`.
4. **Сроки:** сохранена прежняя *календарная* модель: при новой подписке начало — сегодня в 00:00 МСК, конец — через N календарных дней в 23:59:59 МСК. Это **не ровно 30×24 часа**. Изменять правило для уже оплаченных подписок без отдельной миграции не рекомендуется.
5. **Ручные переводы:** клиент получает подтверждение «доставлено администратору» только после успешного `send_photo`. В случае сбоя — сообщение о недоставленном подтверждении, без просьбы отправлять платёж повторно.
6. **HTML:** экранируются поля имени/username/тарифа в уведомлениях об оплатах, чтобы Telegram не разбирал пользовательское имя как HTML.
7. **Валюты:** `USDT_RUB_RATE` вынесен в `.env` (значение `90` — пример, а не актуальная биржевая котировка). Одна настройка используется при создании и сверке CryptoBot-счетов. **Нельзя менять курс, пока висят неоплаченные криптосчета:** в заказах услуг курс на момент выставления отдельно не фиксируется; это оставшийся риск, требующий миграции хранилища котировки.
8. **Telegram initData:** срок действия сокращён с 24 часов до 1 часа, отрицательная погрешность и устаревшие сессии отклоняются. После истечения срока нужно открыть Mini App заново.
9. **Спонсорский канал:** фильтр включён также для `callback_query`; при ошибке Telegram API проверка *запрещает* обработку (fail closed), а не пропускает пользователя.
10. **Админка — блокировка/мут:** новые колонки `users.is_blocked`, `blocked_until`, `block_reason`, `muted_until` (`TIMESTAMP` для ограничений — **naive UTC**, отдельно от московского времени подписок). Владельцу доступны кнопки в карточке клиента. Блокировка запрещает message/callback и все `/api/app/*`/`/api/admin/*`, а также выдачу ссылки и запрос вступления в канал. Мут ограничивает сообщения/кнопки бота, не лишая действующей подписки. Сотрудников и владельцев нельзя ограничивать через API. Автоматическая проверка времени окончания мута/блока не требует cron: она выполняется при обращении.
11. **Смена тарифа:** в карточке клиента можно сменить тариф **в том же канале** атомарно с сохранением старого срока или с новым сроком плана. **Перенос между разными каналами не реализован**: внешние ban/unban Telegram нельзя надёжно включить в транзакцию БД. Для этого используйте «Отозвать» и «Выдать», контролируя переход вручную.
12. **Промокоды:** активация и учёт `max_uses` одного промокода теперь выполняются внутри транзакции с блокировкой строки промокода. Ограничение количества неудачных попыток по-прежнему хранится *в памяти* и не подходит для кластера из нескольких процессов.
13. **Docker:** файлы `.env`, логи, `.git`, `venv` исключены из сборочного контекста через `.dockerignore`. `docker-compose.yaml` загружает секреты из `.env` с помощью `env_file`, слушает HTTP **только на 127.0.0.1** (подразумевается HTTPS reverse proxy). `network_mode: host` заменён на bridge + `ports`, добавлен `host.docker.internal:host-gateway`. Системный TZ — UTC, поскольку платежи/логи/статистика уже рассчитаны на UTC; московская дата подписки вычисляется отдельно.

## Важно перед обновлением

1. **Сделайте резервную копию PostgreSQL и `.env`** и протестируйте восстановление. Не обновляйте действующую БД непосредственно из этого отчёта.
2. Сравните время истечения **нескольких реальных подписок** в БД с отображаемым в кабинете, особенно если предыдущий Docker работал в UTC. Исторические naive-значения нельзя однозначно интерпретировать без знания TZ старого процесса. При расхождении не запускайте новый cron до миграции даты.
3. При первом запуске `init_db()` добавляет в `users` четыре колонки через `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`. У роли PostgreSQL должны быть права на изменение схемы. Для крупной БД применяйте миграцию в контролируемом окне.
4. Убедитесь, что в `.env` выставлены `BOT_TOKEN`, `ADMIN_IDS`, `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASS`, `DB_NAME` и платежные настройки. Для Docker bridge `DB_HOST=localhost` **не** означает PostgreSQL на хосте: используйте `host.docker.internal` и проверьте `listen_addresses`/`pg_hba.conf`, либо имя службы PostgreSQL в одной docker-сети, либо внешний сервер.
5. Для Mini App укажите публичный `WEB_URL=https://...`, HTTPS reverse proxy должен отправлять запросы на `http://127.0.0.1:8000`. Не выставляйте PostgreSQL наружу. ЮKassa/Tinkoff/Crypto Pay webhooks должны доходить через этот HTTPS-адрес.
6. Секрет `ACCESS_SECRET_KEY`: **существующая** версия в отсутствие ключа использовала производный от BOT_TOKEN ключ. Не подставляйте новый случайный ключ без предварительной перепаковки **уже зашифрованных данных**, иначе старые пароли услуг перестанут расшифровываться. В новой установке отдельный Fernet ключ обязателен по эксплуатационной политике.
7. Проверьте содержимое `.env`: реальные банковские реквизиты, Telegram ID и ключи **не должны** попадать в Git и ZIP с исходниками.

## Пример команд для тестового сервера

```bash
cp .env.template .env
# Отредактируйте .env вручную, установите реальные секреты и правильный DB_HOST.
mkdir -p logs
sudo chown -R 10001:10001 logs
python -m compileall -q src
python -m unittest discover -s tests -v
docker compose config  # проверить результат объединения конфигурации
# После резервной копии и валидации legacy подписок:
docker compose up -d --build
docker compose logs --tail=200 -f bot
```

**Не запускайте реальные платежи в ходе smoke-теста на живой БД.** Проверьте авторизацию Telegram, `/start`, callback, кабинет, смену тарифа, mute/block, обновление времени и платежные уведомления в отдельном тестовом контуре. Понадобится также проверить права бота на `ban/unban/create_chat_invite_link`.

## Непроверенное и дальнейшая работа

- Нет `aiogram`, `aiocryptopay`, `asyncpg` и PostgreSQL в тестовой среде, поэтому **сквозные тесты, включая реальные платежи, блокировки в Telegram и миграцию БД, не выполнялись**.
- **Не выполнена полноценная проверка CVE всего `requirements.txt`.** Старые `aiohttp`, `fastapi`, `starlette`, `cryptography` требуют отдельного обновления после проверки совместимости (не менять вслепую в production).
- **Оплата → подписка** всё ещё не единая атомарная операция БД: если процесс остановится между подтверждением платежа и выдачей подписки, потребуется сверка/восстановление. Не следует считать этот сценарий исправленным.
- Лимит попыток промокодов in-memory, а также in-memory cooldown на заявки/ссылки не глобальны при нескольких экземплярах сервера; для кластера нужен Redis или транзакционная БД.
- Автоматическая ротация пароля услуги при отзыве временной ссылки не реализована.
- Блокировка бота/Mini App не удаляет уже подписанного пользователя из Telegram-канала. Если требуется полное лишение доступа к контенту, отдельно отзывайте подписку.

**Данная сборка — обновление исходного кода для стенда; не подтверждение готовности к production без тестирования на реальном окружении.**
