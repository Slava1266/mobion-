# MOBION бот — мини-апп, услуги, временные ссылки: инструкция для сисадмина

Что добавлено к существующему боту (подписки MOBIONVIP работают как раньше):

| Что | Где в коде |
|---|---|
| Telegram мини-апп (тарифы, подписка, услуги, заявка на ремонт) | `src/webapp/` (`api.py`, `auth.py`, `static/index.html`) |
| Каталог услуг + кнопка «Оплатить» (карта со скриншотом, ЮKassa, CryptoBot) | `src/handlers/services.py`, `src/payments/service_orders.py` |
| Управление услугами из `/admin` → «🧩 Услуги и доступы» | `src/handlers/admin_services.py` |
| Временные ссылки доступа (`/access/<токен>`) | `src/webapp/api.py`, `src/db/DALS/service.py` |
| Шифрование логинов/паролей услуг | `src/utils/crypto.py` |
| Экран согласия перед оплатой услуги (18+, без возврата) — текст `CONSENT_TEXT` | `src/handlers/services.py` |

Новые таблицы в БД: `services`, `access_links`, `service_orders`. Создаются сами при старте
(`create_all`), существующие таблицы **не меняются**, миграции не нужны.

## 1. Что нужно сделать (по порядку)

### 1.1 Домен с HTTPS (обязательно для мини-аппа)
Telegram открывает мини-апп только по HTTPS. Нужен домен/поддомен, например `app.mobion1.ru`,
A-запись на IP сервера и сертификат (Let's Encrypt).

Пример nginx (проксируем всё на порт бота 8000):

```nginx
server {
    listen 80;
    server_name app.mobion1.ru;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name app.mobion1.ru;

    ssl_certificate     /etc/letsencrypt/live/app.mobion1.ru/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/app.mobion1.ru/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```
Сертификат: `certbot --nginx -d app.mobion1.ru`. Порт 8000 наружу открывать не нужно
(контейнер в `network_mode: host`, достаточно, чтобы nginx видел 127.0.0.1:8000).

### 1.2 Файл `.env`
Скопировать `.env.template` в `.env` (если ещё нет) и заполнить/добавить:

```
WEB_URL=https://app.mobion1.ru          # https, БЕЗ слэша на конце
ACCESS_SECRET_KEY=<сгенерированный ключ>
ADMIN_IDS=<числовой Telegram ID владельца>   # несколько — через запятую
```
Ключ шифрования:
```
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```
**Сохраните `ACCESS_SECRET_KEY` отдельно (менеджер паролей).** Если его потерять или сменить,
сохранённые логины/пароли услуг перестанут расшифровываться (придётся ввести заново).
Если ключ не задан, он выводится из `BOT_TOKEN` — тогда при смене токена бота будет то же самое.

`ADMIN_IDS` — числовой ID, не `@username`. Все указанные ID получают уведомления
(«клиент хочет купить», «оплачено», скриншоты оплат, заявки на ремонт).
Чтобы уведомления шли только владельцу — оставить один ID.

> `.env` копируется в образ при сборке (`COPY . .`), поэтому после любого изменения `.env`
> образ нужно пересобирать (п. 1.3).

### 1.3 Пересборка и запуск
```
cd /путь/к/проекту
docker compose up -d --build
docker compose logs -f --tail=100
```
В `requirements.txt` добавлена зависимость `cryptography==44.0.2` (файл в кодировке UTF-16, как и был).

### 1.4 Что должно появиться в логах при успешном старте
```
Мини-апп подключен: /app
Кнопка меню мини-аппа установлена: https://app.mobion1.ru/app
Бот успешно запущен!
```
Если строки про мини-апп нет — `WEB_URL` не начинается с `https://`.

## 2. Проверка после запуска (чек-лист)

1. `curl https://app.mobion1.ru/health` → `{"status":"ok"}`.
2. В боте `/start`: появилась кнопка меню «MOBION» слева от поля ввода и сообщение
   «📱 Открыть мини-апп». В мини-аппе грузятся тарифы.
3. `/admin` → «🧩 Услуги и доступы» → «➕ Добавить услугу» → создать тестовую услугу
   с ценой 10 ₽.
4. С другого аккаунта: «🧩 Услуги» → услуга → «Оплатить».
   Владельцу в ЛС должно прийти «👀 Клиент хочет купить услугу».
5. Оплатить 10 ₽ (карта + скриншот → «Подтвердить», либо ЮKassa/CryptoBot).
   Клиенту приходит «Оплата получена», владельцу — «Оплачена услуга» с кнопками выдачи ссылки.
6. «🔓 Выдать ссылку на 1 ч» → клиент получает кнопку, по ней открывается страница,
   «Показать доступ» выдаёт логин/пароль. Повторная выдача и «Отозвать» в админке работают.
7. Удалить/скрыть тестовую услугу.

## 3. Платежи: настройка вебхуков

Для автоматической оплаты (ЮKassa, CryptoBot) платёжные системы должны достучаться до сервера:

| Система | URL уведомлений |
|---|---|
| ЮKassa | `https://app.mobion1.ru/payments/youkassa/yoo-notification` |
| CryptoBot | `https://app.mobion1.ru/payments/cryptobot/cryptobot-notification` |

Для оплат услуг подтверждение **перепроверяется** запросом в API самой платёжки
(ЮKassa `find_one`, CryptoBot `get_invoices`), а не берётся из тела вебхука, — подделать
запрос «оплачено» нельзя. Повторные уведомления дублей не создают.

Tinkoff для услуг не подключён.

## 4. Безопасность и эксплуатация

- Логины/пароли услуг хранятся в БД зашифрованными (Fernet). В админке пароль не показывается;
  сообщения с вводом логина/пароля бот удаляет.
- Ссылка `/access/<токен>`: токен 192 бита, срок жизни и отзыв, страница не показывает секреты
  до нажатия «Показать доступ» (предпросмотр ссылки в Telegram доступ не тратит),
  заголовки `no-store`, `noindex`, `no-referrer`.
- Мини-апп проверяет подпись Telegram `initData` (HMAC по токену бота); без неё API отвечает 401.
- Публичная документация API (`/docs`, `/redoc`, `/openapi.json`) отключена.
- Резервные копии: БД PostgreSQL (в ней теперь и услуги/заказы) + `ACCESS_SECRET_KEY`.
- Откат: вернуть прежнюю версию кода и пересобрать. Новые таблицы можно оставить — они ничему не мешают.

## 5. Известные особенности прежнего кода (не менялись, на заметку)

1. **Tinkoff для подписок**: в `src/payments/tinkoff.py` функция `create_payment` требует `order_id`,
   но `tinkoff_payment_route` его не передаёт (и в `user_id` кладёт Telegram ID вместо ID из БД) —
   оплата подписки через Tinkoff, вероятно, не работает. Если он включён (`TINKOFF_ENABLED=true`), стоит проверить.
2. **ЮKassa для подписок**: в `src/webhook.py` у `/yoo-notification` стоит `#TODO: проверка подписи`,
   то есть подписку можно «оплатить» поддельным запросом. Рекомендуется закрыть (проверка платежа через API,
   как сделано для услуг, либо ограничение по IP-адресам ЮKassa на nginx).
3. **ЮKassa return_url для подписок** ведёт на несуществующий `/payments/youkassa/return` (после оплаты — 404).
4. **CryptoBot**: курс USDT/₽ зашит константой 90 (`usdt_amount = round(final_price / 90, 2)`),
   в том числе для оплаты услуг.
5. **Вебхук CryptoBot** принимает тело как есть; для услуг формат учтён в двух вариантах
   (плоский счёт и обёртка `{"payload": {...}}`). Проверить на первой реальной оплате.
6. Состояния диалогов хранятся в памяти (`MemoryStorage`): при перезапуске бота незавершённые
   диалоги (например, ожидание скриншота) сбрасываются.
